# git-diff-analysis

把"时间相关"收敛成"代码相关"。**关键不是 diff 有多大，是改动是否落在异常的调用链上。**

## 关键查询

```bash
LAB='node "$INCIDENT_LAB"'

# 部署窗口内的提交
$LAB git log --since 2026-10-20T13:00:00 --until 2026-10-20T14:30:00 --limit 20

# 逐个看改动点，先看摘要再决定要不要看全量
$LAB git show <sha>
$LAB git diff <sha>
```

## 判断启发

对照 `log-triage` 给出的**栈顶方法名**，在 diff 里找是否改到了同一文件或同一调用链：

| 现象 | 结论 |
| --- | --- |
| diff 改动的文件在栈顶方法所在调用链上 | 强候选根因，继续确认机制 |
| diff 改了文件但不在调用链上 | 记录为"无关变更"，不要写进根因 |
| 窗口内无提交 | **明确写"窗口内无代码变更"**，这是排除依据，不是"没查到" |
| 多个提交同时改动调用链 | 逐个判断，不要合并成一句"最近有几次发布" |

## 常见失效机制对照

| diff 里出现的东西 | 可能机制 |
| --- | --- |
| 新增方法调用但没有判空 | 下游返回 null → NPE |
| 新增 `@NotNull` / `@Valid` 校验 | 请求被拒 → 4xx |
| 调小 timeout / 调大连接池上限 | 资源或下游超时 |
| 删除索引 / 改变查询条件 | 慢查询 |
| 删除兜底分支 | 空值或异常路径不再被处理 |

## 输出

```text
候选 commit：<sha> <标题> <时间>
关联证据：改动了 <改动所在的方法>，与日志栈顶方法一致
失效机制：<一句话：哪个调用拿到了什么、为什么变成这个异常>
```

> 示例里不要填具体方法名或机制——那等于把答案写在契约里。占位符要由当轮证据填。

## 不要做的事

- 不要输出整个 diff。只输出与调用链相关的片段 + 一句机制说明。
- 不要在窗口内无提交时沉默。**"窗口内无代码变更"本身就是排除发布假设的证据**，必须写出来。
