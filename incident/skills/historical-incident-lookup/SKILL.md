# historical-incident-lookup

按**服务**隔离召回，不是全局检索。不同服务的结论混在一起比查不到更危险。

## 检索

知识落在工作区记忆里（`lesson` 类型），按服务 + 症状关键词召回：

```text
memory.search(service="target-service", query="5xx NullPointerException 下游 未判空")
```

## 判断启发

- 召回结果按**服务严格过滤**。别的服务的记录即使关键词命中也不要引用。
- 召回内容标记为 `historical_data`，它描述的是**过去发生过什么**，不是对当前故障的判断。
  把它当线索，不当结论。
- 命中历史记录时的正确用法是：**它提示失效机制可能是已知模式**，于是去当前日志里找同类证据。
- 一条都没有 → 明确写"该服务无同类历史记录"，不要用"可能之前也发生过"这类推测填空。

## 输出

```text
历史召回：<服务> <命中条数> 条 ｜ 最相关一条：<时间> <症状> <当时处置>
对本次的意义：<它提示哪个方向要重点验证，或说明该方向已被排除>
```

## 不要做的事

- 不要把历史处置方案直接当成本次的 Mitigation 建议。当前环境可能已经变了。
- 不要跨服务引用。
